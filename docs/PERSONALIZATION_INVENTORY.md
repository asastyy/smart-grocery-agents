# Роль 2: персонализация и домашние запасы

## Что реализовано

Планировщик получает уже нормализованные рецепты роли 1, профиль пользователя и
подтверждённые домашние запасы. До обращения к LLM Python-код исключает рецепты,
которые нарушают аллергенные, диетические, вкусовые ограничения или лимит времени.
Неизвестный аллергенный состав считается небезопасным, если у пользователя есть
аллергия.

Оставшиеся рецепты ранжируются по мягким признакам: любимая кухня, цели питания,
использование домашних и скоро истекающих продуктов, количество отсутствующих
ингредиентов. Для каждого решения сохраняются причины. Отсутствие мягкой метаинформации
не исключает рецепт.

LLM не проверяет безопасность и не придумывает рецепты: она может только составить
меню из переданных идентификаторов кандидатов. Корзина и бюджет по-прежнему
рассчитываются детерминированным кодом.

## Инвентарь

`InventoryItem` хранит идентификатор партии, количество, единицу, срок годности,
признак вскрытия, статус, источник и уверенность. В план попадают только доступные,
непросроченные записи с `confidence = 1`.

История покупки, чек, штрихкод или фотография создают `InventorySuggestion`, но не
доказательство наличия. Пользователь должен подтвердить количество и единицу, после
чего запись становится инвентарём с полной уверенностью.

При планировании остатки не изменяются. После подтверждения приготовления
`plan_consumption` распределяет расход по принципу FEFO (сначала ближайший срок), а
`apply_consumption(..., confirmed=True)` создаёт новый снимок остатков и события.
Автоматической конвертации несовместимых единиц нет, отрицательные остатки запрещены.

## Контракты и точки подключения

- `src/smart_grocery/schemas/integration.py` — общий профиль и расширенный инвентарь.
- `src/smart_grocery/schemas/personalization.py` — решения, подсказки и события.
- `src/smart_grocery/tools/personalization.py` — фильтрация и ранжирование.
- `src/smart_grocery/tools/inventory.py` — доступность, FEFO и подтверждённое списание.
- `src/smart_grocery/workflow/integration.py` — подключение результата к общему pipeline.

Модуль принимает небольшой набор структурно готовых `Recipe`, а не загружает все
522 798 записей в память. Поиск роли 1 должен сначала выдать релевантную выборку.
Рецепты без надёжных количеств и единиц остаются доступны для просмотра, но не для
автоматического планирования и закупки.

## Автономная проверка

```powershell
python scripts/run_personalization_demo.py
python -m pytest tests/test_personalization.py tests/test_inventory.py -q
```

Демо сравнивает пять профилей на одном проверенном пуле рецептов. Сетевой доступ и
API-ключ для него не нужны.

## Ограничения

- бюджет проверяется после формирования меню и получения цен роли 3;
- единицы не пересчитываются без отдельной таблицы преобразований;
- факт приготовления должен подтвердить пользователь или доверенная интеграция;
- неизвестные аллергены блокируют рецепт только при активной аллергии;
- история покупки не доказывает, что продукт всё ещё находится дома.
