# Проверка корзины и отображение невалидного меню

Предлагаемый заголовок PR: `Fix grocery validation and show incomplete estimates clearly`

## Что исправлено

При ингредиенте в граммах расчёт раньше применял цену за условную порцию.
Теперь единицы, отличные от `portion`, отклоняются. Если цена отсутствует,
сообщение содержит продукт и количество, а результат явно предупреждает
о неполных списке покупок и сумме. Неполный результат всегда невалиден.

Интерфейс раньше показывал зелёное сообщение даже при невалидном меню.
Теперь он показывает предупреждение и причины отдельно, а сумму обозначает
как предварительную. Покупки представлены таблицей, исходный JSON доступен
в раскрываемых деталях. Пустая корзина при ошибках не означает отсутствие
необходимости покупать продукты.

Общие модели и сигнатуры функций не изменены. Добавлены исключения Git для
локального окружения, кешей и `.env`, а также инструкция запуска на Windows.

## Проверка

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q
```

Результат локальной проверки: **21 passed**. Из них 15 сценариев расчёта,
4 сценария интерфейса через Streamlit AppTest и 2 исходных теста.
Проверки выполняются без реального LLM. Пользователь также подтвердил
успешную ручную проверку приложения в браузере. Docker и вызовы внешнего
LLM на этом этапе не проверялись.

Контрольный вход и полный ожидаемый JSON находятся в `docs/ROLE_3.md`.

## На что обратить внимание ревьюерам

- Участник 4: представление ошибок, таблица корзины и предварительная сумма
  в `app.py`. Проверить вручную обычный запрос и бюджет 0.
- Участник 1: цены за `portion` и соответствие тегов диеты составу рецептов.
- Команда: при неизвестной цене позиция пока отсутствует в `shopping`, но
  указана в `issues`. Для неизвестной цены внутри самой таблицы потребуется
  согласованное изменение схемы.

Количественный pantry, масштабирование порций и отдельный LLM-критик пока
не реализованы. Текущий mock-планировщик не меняет меню по замечаниям;
проверки интерфейса подтверждают честное отображение неудачи после попыток,
но не доказывают успешную LLM-перепланировку.
