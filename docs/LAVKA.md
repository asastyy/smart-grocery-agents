# Проверка Яндекс Лавки

Проверено 26 ноября 2026 года. Это исследование доступности и данных; работающий программный адаптер Лавки пока не добавлен.

## Что действительно работает

В обычном браузере без входа в Яндекс выбран публичный адрес Канатного цеха НИУ ВШЭ: Санкт-Петербург, 25-я линия Васильевского острова, 6к1. Сайт подтвердил зону доставки. Выполнены поиск риса, поиск молока и открытие карточки риса. До выбора адреса сайт явно показывал демо-каталог.

В карточке риса Prosto подтверждены упаковка 500 г, отображаемая цена 84 ₽, обычная цена 169 ₽, состав и КБЖУ на 100 г. Условия применимости скидки к конкретному заказу не проверены: для консервативной оценки использовать 169 ₽. Для 600 г потребности это 2 упаковки, 338 ₽ и остаток 400 г. Это оценка по карточке, не подтверждённая сумма заказа; доставка и сборка не включены.

У молока «Домик в деревне» на экране 930 мл, но в URL осталось 955 мл. Объём нельзя извлекать из slug. В рисовой выдаче встречаются готовые каши и рекомендации: совпадение поискового слова ещё не означает подходящий ингредиент.

## Что не подтвердилось

Один прямой анонимный запрос к `/api/v1/providers/search/v3/lavka` без адресного контекста вернул HTTP 401; главная страница — 200. Это конкретный результат такого запроса, а не доказательство, что весь каталог требует входа: через сайт адресный поиск работает без входа. Cookies из браузера не извлекались.

На первом этапе MCP не запускался; затем по отдельной просьбе пользователя установлен и проверен пакет PyPI `yandex-lavka-mcp==0.1.6`. Его текущая инструкция требует сессию и местоположение. Поиск и карточки в браузере не доказывают работоспособность MCP. Официальный публичный товарный API этой проверкой не установлен.

## Что учесть при подключении

- В исходном `LavkaClient._trim_product` отсутствие наличия превращается в `True` через значение по умолчанию. Это неприемлемо для наших проверок: отсутствие поля должно давать `unknown`.
- Передавать адресный контекст в каждый поиск, не смешивать предложения разных складов и времени получения.
- Использовать видимые/структурированные поля упаковки; не выводить объём из массы и не разбирать размер из URL.
- Разделять акционную и обычную цену; право на скидку подтверждать отдельно.
- Состав не доказывает отсутствие аллергенов и следов; остаток в штуках также не установлен.
- Для программного эксперимента нужен отдельный локальный профиль/сессия с явно настроенным доступом. Cookies не передавать в чат и GitHub. Сторонний MCP запущен по явному запросу пользователя после ограниченного обзора кода; операции корзины и оплаты для поиска не нужны.

Подготовить ограниченный клиент только для поиска и карточки; настроить его локально и повторить те же запросы. После получения исходного адресного JSON добавить нормализацию, контрактные тесты и сравнение упаковок с ВкусВиллом. До этого в приложении нельзя обозначать Лавку как подключённый магазин.

## Фактический запуск неофициального MCP

Установлен wheel 0.1.6 из PyPI в отдельное временное Python-окружение, зависимости согласованы (`pip check`). Перед запуском прочитаны код конфигурации, входная точка, клиент, инструменты и адреса запросов. Это ограниченный обзор, не независимый аудит безопасности.

Реальный MCP-тест по stdio: `initialize` успешен, `tools/list` вернул 22 инструмента, `lavka_status` вернул `authenticated=false`, `location_set=false`. Вызваны только status, поиск риса и карточка риса. Оба товарных инструмента вернули `ok=false`, `Not signed in`. Важно проверять поле `ok`: протокольный `isError=false` здесь не означает успешный поиск.

Это локальный отказ по проверке конфигурации сервера до обращения за товарами, а не новый ответ товарного API. Версия пакета требует входа даже для тех данных, которые сайт показывает гостю. Проверка не обходилась, фиктивные cookies не подставлялись.

[Результат MCP-теста](../fixtures/retail/lavka_mcp_probe.json). Платёжные инструменты присутствуют в списке сервера, но не вызывались. Сервер запускался дочерним процессом и завершился после теста, HTTP-порт не открывался. В окружение передана явно пустая конфигурация, пользовательские настройки, cookies и ключи не читались.

### Подготовка сессии пользователем

1. Войти в собственный аккаунт на `https://lavka.yandex.ru/` в браузере, выбрать адрес Канатного цеха.
2. Открыть инструменты разработчика → Network, выполнить поиск, выбрать запрос к `lavka.yandex.ru` → Request Headers → Cookie. Скопировать только значение этого заголовка. Не отправлять его в чат, GitHub или группе.
3. В своём терминале из корня проекта выполнить `python3 scripts/lavka_session_setup.py` и вставить значение в скрытое приглашение. Скрипт не извлекает cookies из браузера: сохраняет только введённое пользователем значение в `outputs/lavka-private/config.json` с правами 600. Каталог outputs исключён из Git. Существующий файл не перезаписывается.
4. После локальной настройки повторить `lavka_status`, через MCP задать публичный адрес и проверить поиск/карточку. До этого реальные товары через MCP остаются непроверенными. Сам вход в браузер не переносит сессию в MCP.

Сессионные cookies дают доступ к аккаунту; подключение использовать только локально. При обнаружении CAPTCHA потребуется участие пользователя. Экспорт cookies браузерными скриптами, доступ к Keychain и операции корзины для этой проверки не выполнялись.
