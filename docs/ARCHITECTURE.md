## Основной процесс

Точка входа интерфейса — `app.py`. Каталог Food.com обрабатывает
`run_foodcom_workflow` из `src/smart_grocery/workflow/foodcom.py`.

| Модуль | Ответственность |
|---|---|
| `app.py` | Запасы и условия, меню, корзина, история попыток |
| `tools/recipes.py` | Загрузка данных и поиск допустимых кандидатов |
| `agents/planner.py` | Выбор блюд через LLM, проверка ответа и ID |
| `tools/budget_v2.py` | Порции, запасы, цены и проверка ограничений |
| `agents/validator.py` | Связь плана с каталогом, оценка и рекомендации |
| `agents/critic.py` | Рекомендации по вычисленным нарушениям |
| `workflow/foodcom.py` | Максимум две попытки, передача рекомендаций, история |

Планировщик получает ограниченный набор кандидатов, выбирает обед и ужин
на каждый день и возвращает структурированный ответ. Python проверяет меню.
При нарушениях рекомендации критика передаются в следующую попытку.
Если кандидатов нет, возвращается `no_candidates` без вызова планировщика.

## Границы ответственности

**LLM:** выбор блюд и рекомендации. Используются допустимые ID; вход и выход
проверяются кодом. Критик не меняет корзину, стоимость и `valid`.

**Python:** количества, учёт запасов, стоимость и нарушения ограничений.
При неизвестной цене полная стоимость остаётся `null`, оценённая часть
отображается отдельно как `priced_subtotal`.

**Интерфейс:** запрос, итоговое меню, покупки, предупреждения и история.
Локальный `.env` содержит конфигурацию провайдера.

## Обработка сбоев

- Некорректный JSON: проверка схемы и ограниченный повтор запроса.
- Неизвестный ID: отклонение ответа, выбор ограничен кандидатами.
- Недоступный API планировщика: резервный выбор из допустимых кандидатов.
- Сбой критика: результат Python сохраняется.
- Нарушения после второй попытки: результат с нарушениями.

Два прохода цикла не означают ровно два HTTP-запроса: обработка некорректного
ответа модели может включать отдельный повтор.

## Выбор инструментов

| Инструмент | Назначение |
|---|---|
| Gemini | Планировщик и критик через настраиваемый API |
| Pydantic | Проверка структур данных на границах модулей |
| Streamlit | Локальный интерфейс |
| pytest | Модульные и интеграционные проверки |
| Docker Compose | Воспроизводимый запуск |

Цикл на Python содержит один условный переход и максимум две попытки.
LangGraph станет полезен при дополнительных ветвях, длительных операциях
или сохранении состояния между сессиями.

## Совместимость

`workflow/runner.py`, `tools/budget.py` и `tools/legacy_recipes.py` обслуживают
ранний формат примеров и проверки совместимости. Текущий интерфейс использует
Food.com-процесс. Эти модули нельзя удалять без проверки зависимых тестов.

См. [контракты](CONTRACTS.md), [подготовку данных](DATA_NOTES.md)
и [настройку критика](CRITIC.md).
