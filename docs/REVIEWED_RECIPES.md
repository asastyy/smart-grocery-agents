# Первые 50 рецептов для планирования

Подготовлены 28.11.2026 поверх общей версии. Все 50 прошли редакционную проверку по сохраненным источникам; пробное приготовление и независимая проверка человеком не проводились.

## Что находится в наборе

44 блюда для обеда/ужина и 6 для отдельного плана завтраков. У каждой записи есть исходное число порций, количества и единицы всех обязательных продуктов, инструкции, тип блюда, допустимые приемы пищи, URL и SHA-256 снимка. Подготовка, приготовление, ожидание и исходное общее время хранятся отдельно; неизвестная отдельная длительность остается `null`.

Исходный Food.com/Wikibooks-каталог не переписывается. В прежней очереди только 17 записей одновременно имели порции и полностью разобранные количества; для готового набора выбран дополнительный источник с явными полями — MedlinePlus.

- `data/reviewed/medlineplus/sources.jsonl.gz`: 50 исходных страниц и извлеченные поля.
- `data/reviewed/medlineplus/corrections.jsonl`: отдельные проверенные проектные варианты и основания каждого изменения.
- `data/reviewed/medlineplus/validation.json`: воспроизводимый отчет.
- `src/smart_grocery/catalog/reviewed.py`: проверка источников, допустимость данных, адаптер Recipe и масштабирование.

Источники: [MedlinePlus / NLM](https://medlineplus.gov/recipes/), [правила использования](https://medlineplus.gov/about/using/usingcontent/), [NIST: единицы](https://nvlpubs.nist.gov/nistpubs/Legacy/LC/nbslettercircular1098.pdf). Медицинские свойства блюд проектом не устанавливаются.

## Как использовать

В приложении: «Каталог рецептов» → «Подготовленные 50». Выберите блюдо и порции: количество ингредиентов пересчитывается; известные определения «штуки» доступны отдельно. Русские инструкции описывают выбранный вариант, полный оригинал остается в снимке. Основания изменений доступны в карточке.

Для меню: «Профиль и запасы» → «Рецепты с проверенными данными · 50». Можно выбрать обед/ужин или отдельный завтрак. При активной аллергии весь набор блокируется. Для сценария без аллергий очистите поле аллергенов только если это действительно соответствует профилю пользователя. Автоматически снимать ограничения приложение не должно.

API:

```python
from smart_grocery.catalog.reviewed import reviewed_planning_recipes, scale_recipe

recipes = reviewed_planning_recipes()
amounts = scale_recipe(recipes[0], people=4)
```

Проверка без сети:

```bash
python scripts/check_reviewed_recipes.py
python -m pytest -q
```

## Существенные исправления

- Pasta Caprese: 3 кварты воды присутствуют только в инструкции. Вода добавлена в полный список с прямой ссылкой на шаг.
- Рыба со шпинатом: 15 минут под фольгой + 20 без фольги, при подготовке 15 минут. Для лимита учитывается 50 минут вместо исходных 45.
- Овсянка на ночь: в шапке 6 часов, в инструкции 6–12. Для планирования используется верхняя граница 735 минут вместе с подготовкой; диапазон ожидания сохранен.
- Энчилада с тофу: два этапа запекания 10 + 30 минут и 5 минут отдыха. Консервативная граница 75 минут может завышать фактическое время из-за перекрытия подготовки. Неполное описание слоев дополнено отдельным проектным вариантом, который использует все исходные количества; замысел автора не объявляется восстановленным фактом.
- Курица в медленноварке: 5 минут подготовки добавлены к верхней границе 8 часов медленного режима. Быстрый режим не подставляется автоматически.
- «По четверти ложки соли и перца» означает отдельную четверть каждого продукта.
- Пакет приправы 1.25 oz переведен в 35.43690390625 g, а не в штуку неизвестного размера.
- Полный вес банки сохраняется до слива жидкости. Выход после слива неизвестен.
- Явные альтернативы фиксируются как проектный вариант с основанием; неизвестные средние количества не придумываются. Необязательные добавки исключаются только с записью об этом.

## Проверки и границы

**305 тестов проходят локально и в контейнере**, включая 65 новых проверок набора. Все 240 прежних проверок сохранены.

Критерий масштабирования проверен на всех 50 рецептах для 1, 2, 4 и 7 человек: 200 комбинаций. Также проверены частичные и избыточные запасы, точечные независимые пересчеты из источника, несовместимые единицы, тип приема пищи и отсутствие изменений исходных объектов.

Любая активная аллергия блокирует все 50 записей до LLM и магазина. `allergens_status=unknown`, `allergens=null`. Список потенциальных аллергенов по названиям ингредиентов — неполное предупреждение, а не разрешающий список. Маркировка составных продуктов и перекрестный контакт неизвестны.

Готовый рис, курица, фасоль и другие подготовленные продукты не превращаются в сырые. Их дополнительное приготовление и выход не оценены. Миллилитры сухих продуктов не превращаются в граммы. Если меню объединяет один продукт в разных единицах, система отмечает несовместимость; универсальная физическая конверсия без основания не добавляется.

Рассчитывается недостающее количество продуктов, а не гарантированная стоимость магазина. Цены и адресное наличие большинства ингредиентов пока неизвестны: полный денежный итог остается неизвестным. Дробные яйца/овощи обозначают расчетную долю; покупка целых упаковок округляется в магазинном модуле. Кандидаты с неоднозначными унциями жидкости исключены: суп с тортильей, суп с ветчиной, минестроне и тыквенный суп с концентрированным молоком. Для них не придуманы объемы или плотность. Время не масштабируется пропорционально людям и относится к исходной партии; размер посуды, мощность техники и количество заходов не проверены.

Положительные диетические теги описывают выбранный вариант по ингредиентам, а не заменяют проверку этикетки. Рецепт с куриным бульоном не помечается вегетарианским даже при спорной категории источника. Пищевая ценность не пересчитывается и не выдается за подтвержденную.

Следующая проверка человеком: приготовить выбранные блюда, измерить объем/массу ключевых ингредиентов, оценить размеры порций и время на другом числе людей, затем подключить соответствующие товары. Это отдельная работа, не скрытая за статусом проверки источника.
