# LLM-критик — готовый интерфейс для команды

`agents/critic.py` реализует отдельную LLM-роль, которую вызывает
`agents/validator.py` после детерминированной проверки невалидного меню.
Критик получает запрос, результат проверки и кандидатов с рассчитанными
Python стоимостями одного блюда. Он объясняет нарушения и рекомендует
действия, но не составляет окончательное меню.

## Подключение Food.com

Для нового контракта используйте `validate_foodcom_plan(request, plan, catalog)`
из `agents/validator.py`. Полный путь: `run_foodcom_workflow(request)` из
`workflow/foodcom.py`, экран — `app_foodcom.py`. Он сохраняет обе попытки
в `agent_trace`, передаёт весь feedback планировщику и пересчитывает новое меню.
При нарушениях второго меню критик также вызывается, но третьей попытки нет.
`evaluate_plan` остаётся детерминированным инструментом без LLM-вызовов.
Старые `validate_plan` и `runner.py` сохранены для legacy-примера.

Исходные нарушения идут первыми, рекомендации — с префиксом
`Critic [LLM, issue N]`. Критик не меняет расчёты и не гарантирует успешную
оптимизацию. Новый план обязательно проверяется Python.

## Режимы и настройки

- `MOCK_LLM=true` (по умолчанию): API не вызывается. Сообщение `Critic [mock]`
  явно указывает, что это заглушка; она не имитирует настоящий LLM.
- `MOCK_LLM=false`: реальный вызов Chat Completions через OpenAI-compatible API.
- `LLM_API_KEY`: ключ, задаётся локально, никогда не коммитится.
- `LLM_MODEL`: модель планировщика и по умолчанию критика.
- `CRITIC_MODEL`: необязательное переопределение модели критика.
- `LLM_BASE_URL`: необязательный адрес провайдера; пустое значение использует
  адрес SDK по умолчанию. Провайдер должен поддерживать JSON mode.

Planner автоматически читает локальный `.env`; переменные процесса имеют
приоритет. Проверенная локальная конфигурация Gemini:

```dotenv
MOCK_LLM=false
LLM_API_KEY=your_gemini_api_key
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_MODEL=gemini-3.5-flash-lite
CRITIC_MODEL=gemini-3.5-flash-lite
```

Ключ хранить только в игнорируемом `.env`. Использовать доступную аккаунту
бесплатную квоту; приложение не проверяет состояние биллинга провайдера.
После изменения настроек перезапустить сервер. Если ранее в PowerShell был
установлен mock-режим, явно изменить его:

```powershell
$env:MOCK_LLM = 'false'
.\.venv\Scripts\python.exe -m streamlit run app_foodcom.py
```

Для проверки оставить запасы пустыми и установить бюджет 0. При успешном
вызове раздел «Работа критика» покажет ответ настоящей модели. При валидном
меню критик не вызывается. `Critic unavailable` означает ошибку API или ответа,
а не успешный LLM-вызов. Отдельный живой тест (обращается к API):

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/check_critic_live.py --live
```

## Валидация и отказоустойчивость

JSON mode обеспечивает формат JSON; структуру дополнительно проверяет
локальная Pydantic-модель с запретом лишних полей. Ответ содержит 1–10
рекомендаций, каждая с существующим индексом ошибки, непустым текстом
и ID только из кандидатов. Некорректный ответ повторяется один раз.
HTTP-ошибки не повторяются SDK; timeout установлен в 20 секунд на запрос.
Тела ошибок провайдера и ключи не включаются в результат или журнал.

Нельзя гарантировать фактическую корректность свободного текста LLM.
Рекомендации не отменяют правила; окончательное решение принимает повторная
проверка. При отсутствии цены критик не должен придумывать её.

Источник для JSON mode и необходимости проверки схемы:
https://developers.openai.com/api/docs/guides/structured-outputs

## Проверка реализации

`tests/test_critic.py` использует настоящий OpenAI SDK и подставной HTTP
транспорт, без сетевых вызовов. Проверены сохранение расчётов, контекст
стоимостей, неверный JSON, неизвестные ID/индексы, запрещённые поля,
fallback, mock-режим, отсутствие конфигурации, отсутствие вызова для
валидного плана и передача рекомендаций в ограниченный цикл пересмотра.

Настоящий ответ Gemini подтверждён отдельным локальным тестом:
`Deterministic facts preserved: True`, `Real critic response validated: True`.
Пользователь также подтвердил работу приложения локально. Это не гарантия
качества всех рекомендаций: при нулевом бюджете промпт требует учитывать
полное покрытие запасами и не выдавать просто более дешёвый рецепт за решение.
