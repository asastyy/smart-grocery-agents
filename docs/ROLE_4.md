# Роль 4: интеграция, интерфейс и запуск MVP

Роль 4 объединяет данные и поиск роли 1, LLM-планировщик роли 2 и расчёт с
критиком роли 3 в один пользовательский сценарий.

## Готовый сценарий

Основная точка входа — `app.py`. Пользователь задаёт запасы с количествами,
бюджет, число дней и людей, а также максимальное время приготовления.
Ограничение MVP — вегетарианское меню с обедом и ужином на каждый день.

Workflow `run_foodcom_workflow` выполняет не более двух попыток:

1. поиск возвращает подходящие рецепты из Food.com;
2. планировщик выбирает ID кандидатов;
3. Python рассчитывает количества и корзину, затем проверяет меню;
4. при нарушениях критик объясняет их планировщику;
5. исправленный план повторно проходит ту же Python-проверку.

Интерфейс показывает сохранённый запрос, меню, корзину, полную или частичную
стоимость, коды нарушений и журнал обеих попыток. После изменения параметров
старый результат явно помечается. JSON можно скачать для отчёта или защиты.
Ошибки API отображаются без текста ответа провайдера и секретов.

Старый `runner.py` сохранён для совместимости с исходными примерами и тестами.
`app_foodcom.py` перенаправляет на основной интерфейс.

## Запуск и проверка

```bash
python -m pytest -q
python scripts/check_data.py
python scripts/run_foodcom.py
python -m streamlit run app.py
```

Docker-образ включает `data/`, запускает приложение от непривилегированного
пользователя и содержит HTTP health check:

```bash
cp .env.example .env
docker compose up --build
curl --fail http://localhost:8501/_stcore/health
docker compose down
```

Шаблон CI находится в `docs/github-tests.yml`. Он не активирован, потому что
текущий GitHub-токен не имеет права `workflow`; владелец репозитория может
перенести файл в `.github/workflows/tests.yml`.

## Gemini

Официальный OpenAI-compatible endpoint позволяет оставить общий клиент роли 2
и роли 3. Рекомендуемая конфигурация:

```dotenv
MOCK_LLM=false
LLM_API_KEY=YOUR_LOCAL_GEMINI_KEY
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_MODEL=gemini-3.5-flash-lite
CRITIC_MODEL=gemini-3.5-flash-lite
```

Документация: https://ai.google.dev/gemini-api/docs/openai/
Модель: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite

Ключ хранится только в `.env`. Для живой проверки сначала запустите обычный
запрос, затем запрос с пустыми запасами и бюджетом 0 CU. Во втором результате
должны появиться `Critic [LLM, issue ...]`, feedback во второй попытке и новая
Python-оценка. Невыполнимый бюджет может остаться невалидным — это корректно.

## Что показать на защите

1. Mock-сценарий как воспроизводимый запуск проекта.
2. Live-сценарий Gemini с названием модели в верхней части интерфейса.
3. Меню и рассчитанную корзину.
4. Бюджет 0 CU, нарушения, совет отдельного критика и вторую попытку.
5. Объяснение, что LLM выбирает и советует, а цены и валидность считает Python.

## Ограничения

- Цены синтетические и указаны в условных единицах CU.
- Пошаговых инструкций приготовления в наборе нет.
- Часть исходных количеств хранится в `pcs`; несовместимые единицы не
  конвертируются автоматически.
- Live-проверка требует локального Gemini API-ключа.
