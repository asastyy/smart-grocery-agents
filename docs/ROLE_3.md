Рабочая ветка: `feature/budget`. Расчёт находится в
`src/smart_grocery/tools/budget.py`, вход валидатора — в

## Запуск на Windows

Из корня репозитория, после создания `.venv` и установки `requirements.txt`:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$env:MOCK_LLM = 'true'
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Активация окружения и API-ключ для тестов не нужны. Интеграционный тест
принудительно использует `MOCK_LLM=true`.

## Контрольный пример

Вход: `examples/request.json`, рецепты из `examples/recipes.json`, выбранное
меню `['omelette', 'rice_bowl']`. Яйца и помидоры уже есть дома.
Ожидаемый результат при ценах из примера:

```json
{
  "recipe_ids": ["omelette", "rice_bowl"],
  "shopping": [
    {"item": "beans", "quantity": 1.0, "unit": "portion", "unit_price": 1.1, "cost": 1.1},
    {"item": "cheese", "quantity": 1.0, "unit": "portion", "unit_price": 1.5, "cost": 1.5},
    {"item": "rice", "quantity": 1.0, "unit": "portion", "unit_price": 0.9, "cost": 0.9}
  ],
  "total_cost": 3.5,
  "currency": "EUR",
  "valid": true,
  "issues": []
}
```

Цены демонстрационные, не розничные. Текущий контракт учитывает pantry как
неограниченную доступность; `servings` не масштабирует ингредиенты.
Диета проверяется по тегам рецепта, поэтому корректность тегов важна.

## Обработка неполных данных

Цена относится к `portion`. Другие единицы отклоняются, даже если продукт
есть дома. При неизвестной цене сообщение содержит название и недостающее
количество. Такие позиции не входят в `shopping`, поскольку текущая схема
требует числовую цену. В `issues` явно указано, что список и сумма неполны,
а `valid` равен `false`. Нулевую цену вместо неизвестной не подставляем.

Для отображения всех позиций с неизвестной ценой нужно отдельно согласовать
расширение общей схемы и поведение интерфейса с командой.
