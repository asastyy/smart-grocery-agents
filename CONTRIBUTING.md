# Работа с репозиторием

[На главную](README.md) · [Документация](docs/README.md)

Создавайте отдельную ветку от актуальной `main`, например `feature/recipe-search`
или `fix/missing-price`. Один PR решает одну согласованную задачу.
Сохраняйте общие форматы из [контрактов](docs/CONTRACTS.md).

## Проверки перед PR

Из корня проекта в установленном Python-окружении:

```bash
python -m pytest -q
python scripts/check_data.py
```

Для изменения процесса или интерфейса дополнительно:

```bash
MOCK_LLM=true python scripts/run_foodcom.py
```

В PowerShell задайте `$env:MOCK_LLM="true"` перед запуском скрипта.
Проверьте обычный запрос и сценарий, который затронуло изменение.
Для документации проверьте ссылки, команды и отображение.

## Описание PR

- Задача и итоговое поведение.
- Способ проверки и результат.
- Скриншот, если меняется интерфейс.
- Существенные ограничения или изменение контрактов.

Шаблон описания появится автоматически. Изменения общих контрактов согласуйте
с участниками, чьи модули используют данные.

## Данные и конфигурация

В Git входят подготовленные `data/`, небольшие примеры и тестовые данные.
Сырые выгрузки `data/raw/`, `.venv/` и локальный `.env` исключены.
Ключи не добавляйте в код, скриншоты, логи и обсуждения. Новую обязательную
переменную добавляйте в `.env.example` с пустым значением или шаблоном.

Для ошибки или предложения используйте шаблон Issue.
